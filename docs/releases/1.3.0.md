Client 1.3.0 adds software inventory for the ClientProxy console. On every successful tunnel connection/reconnection, it sends its compiled version, OS, architecture, Cargo target and installation method once. The coordinator preserves this report and shows version comparisons and platform-specific update instructions.

- No periodic reporting or automatic upgrades. Failed reports do not stop traffic; the previous database inventory remains available until a later connection reports successfully.
- Reporting has an eight-second timeout and is cancelled if the tunnel session ends.
- Debian/RPM, Docker, Synology and Windows service packaging identify their installation method. Older Windows service XML can keep existing credentials and add the environment marker from the new template; otherwise choose the service method manually in the console.
- Existing configuration endpoints and tunnel protocol remain unchanged. Older coordinators can reject optional reporting without preventing normal tunnel traffic. Existing Proxy HTTPS and TLS passthrough requirements are unchanged.

Deploy the upgraded coordinator before upgrading clients. Server 0.12.0 adds equivalent server inventory; no newer server protocol is required for this optional client reporting.

These assets are built and published only when the matching `v1.3.0` tag is pushed. Local builds are validation only.
