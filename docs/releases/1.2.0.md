Client 1.2.0 adds TLS passthrough alongside Proxy HTTPS, configurable per domain mapping in the ClientProxy dashboard. One client connection can carry both modes.

- Relays browser TLS unchanged to the configured local HTTPS listener. The site private key stays on your machine.
- Uses bounded, flow-controlled streams with cancellation and graceful close for large transfers and simultaneous traffic.
- Checks coordinator requirements against server configuration and refuses silent downgrades of passthrough mappings.

Requires server **0.11.0** and the upgraded coordinator for passthrough. Existing Proxy HTTPS mappings remain compatible. Passthrough requires a TLS-capable product without HTTP request quotas, HTTP/3 disabled on the proxy, and a local TLS listener with a certificate for the public hostname. Certificate generation/renewal is not included; no new CLI flag is needed.

Includes Linux amd64/arm64 Debian and RPM packages, Linux amd64/arm64/armv7 binaries, the Windows installer ZIP, and a Synology DSM 7 package with increasing build number **1002000**. Container images: `ghcr.io/clientproxy-io/tunnel-client:1.2.0` and `:latest`. Release assets include SHA-256 checksums.

Validation: client/server Rust tests, Synology packaging tests, local mixed-mode end-to-end tests, and live Oracle checks of both modes, certificate identity, large transfers and concurrent connections. Live tests used explicitly trusted temporary certificates.
